# Changelog

## 2026-09-23

- Two regexes added today held literal line-separator and bidi characters where the rest of the generator writes `\u` escapes. They matched the same text, but an editor shows nothing there and can drop or reorder them without anyone noticing. They're escapes now, and a test fails if any script, the test file included, gains one.
- The PR delivery checklist now describes the settings it's given. It's only built when a repository has workflows, yet in five of the six combinations of settings its evidence said the hosted workflows were absent, and with Actions PR creation off or unknown it advised staying offline-only instead of running a merge drill. It now says what it found (PR creation off, unreadable, or allowed) and asks for the drill before required checks are turned on, or while they're on if they already are. The admin-enforcement blocker no longer asks for a drill "before required checks are enabled" when they already are, and a ruleset that enforces the checks no longer comes with a blocker saying branch protection doesn't. This repository has no workflows, so its own report didn't change.
- The tests really don't write into the repository's cache now. An earlier entry today said they didn't, but four tests start the generator in a separate process without a cache path of their own, so each run took the run lock under `.cache/profile-sync` in the checkout, left `run.lock` behind, and could sit waiting on a real run's lock for up to 15 minutes. Each now uses its own folder under the test drive, and a test fails if another child run of the generator is added without one. Two dependency review tests had the same problem with `.cache/registry-versions.json`, which they refreshed from the live npm and PyPI registries. They now read a fresh registry answer from the test drive and stay offline, and the same kind of test guards them.
- Backticks in catalog or GitHub text are escaped now. A code span binds before a link, so a title like ``Tick`Tool`` next to a description with its own backtick turned everything between them into code and the project link disappeared. Escapes also show as written inside a code span, so a path in backticks came out with doubled backslashes. The encoder's own description now says plainly that GitHub still links a bare URL in text by itself, which adds no row, cell or element and isn't something it tries to stop. No current README row had a backtick, so the page didn't change.
- Catalog URLs and names can't break a README row anymore. A review found that a catalog `liveUrl` could carry a line break and a whole second table row into the README with no check firing, and a `|` in one split its cell. `liveUrl` and `userscriptUrl` now have to be http or https URLs of printable ASCII with no space, quote, angle bracket, backslash or pipe, in the catalog check and in its schema, and the action link percent-encodes `|` and `\` too. Plain http is still left to the URL scheme check, so each gate fails for one reason. `language` gets the same one-line check as the rest of the public text. Repository names, aliases and ids end at the true end of the text, and ids are checked case-sensitively like the schema does. The feed's `branch`, which can come from GitHub's default branch instead of the catalog, has to match the catalog's branch shape.
- The README header's personal text now comes from the catalog. The tagline, the language line, the greeting, the about paragraph, the "More about what I do" link and the Ko-fi button were written into the generator, so a run for another account opened with "Hey, I'm Matt" above its own catalog. They now live in a `profileHeader` block in `data/profile-catalog.json`. The catalog check holds that text to the same one-line rules as the rest of the public text, and its links must be https URLs that can't break out of an HTML attribute. A catalog without the block gets a neutral header, "Public projects by" the owner plus the category links. This profile's README didn't change by a byte. The rendered smoke check also opens the profile of the owner it's given now, where it always opened this one.
- Fixed two bugs the header block turned up. Drafting catalog rows for new repositories rewrote every array in the catalog as a `{"__JsonArray": true, "Items": [...]}` object, and preparing a value for schema validation turned a one-item array into that item, so the header's single link failed the catalog schema. Neither showed up before because the catalog had no arrays below its list of entries.
- Dropped the half of the README header check that could never pass. It still accepted the old SVG header, which needs theme-aware header and footer images with their own alt text, and the generator stopped drawing those when the README went text-only. Its two report fields, `themeAwareImageChrome` and `meaningfulImageAltText`, were false on every run and are gone from the report and its schema. A README that still carries the old header fails the check, and a test now shows it.
- The README's install snippets are now one short line each: `irm https://raw.githubusercontent.com/SysAdminDoc/SysAdminDoc/main/run.ps1 | iex; Start-Tool <Name>`. Each of the 61 projects that has one used to carry the full clone-and-run command, 235 to 313 characters long. The first-time setup section explains the short line and shows the full command it stands for. The link check now follows each `Start-Tool` line to the entry script it will start, and checks `run.ps1` itself, since every line depends on it.
- `run.ps1` no longer hands a stricter error setting to the tool it starts. It set `$ErrorActionPreference` to `Stop` for its own steps and the tool's script inherited it, so a tool written for PowerShell's default would have quit at its first minor error. No README line used `run.ps1` before today, so nobody ran into it. When `git` can't update an old copy, the error now says to delete the folder and try again. A new test runs the short line end to end in Windows PowerShell 5.1, through `iex` the way a visitor pastes it.
- Added `run.ps1`, a small script that fetches and starts any of the profile's PowerShell or Python tools by name. It looks the project up in the public feed, checks every value it's about to hand to `git`, `pip` or the shell, and works in Windows PowerShell 5.1. The catalog check now also requires `installKind` to match the entry script, `.ps1` for PowerShell and `.py` or `.pyw` for Python, because `run.ps1` relies on the two agreeing.
- OpenSSF Scorecard now runs locally when asked. The report used to show the hosted Scorecard score, 6.7 from a scan on 2026-06-25 of a three-month-old commit, marked as available, because the hosted service only rescans repositories that run the Scorecard workflow and this one no longer has any workflows. `-RunScorecard` runs the Scorecard v5 CLI with the `gh` token instead and records the score and every check with its reason. Without the switch, or without the binary, the section says why it's unavailable. The check that looked for a Scorecard workflow is gone too.
- Finished the failure-condition tests after review. The earlier claim that every blocking condition had a test that fires it wasn't true for release verification, whose case only checked the switch; it now plants a checksum mismatch and watches the run fail. The report half of the schema check and link failures from live probes each got their own case too, since either could have been disconnected unnoticed. Every case now checks the exact set of conditions that fire, and names any a plant fires by its nature, such as a duplicate catalog row also being a duplicate feed row. The runtime and rendered-smoke inputs are pinned, so the results don't depend on the machine. The tests no longer write into the repository's validation cache, and nothing after the rendered-smoke tests can run online by accident.
- Tightened the schema fields that name this profile's repository after review. The patterns that replaced the exact `SysAdminDoc/SysAdminDoc` values let through a trailing line break, because in .NET a `$` also matches before a final newline, and also `..` segments and any `owner/repo` pair. They now require the same name twice, as in `owner/owner`, and end at the true end of the text. The same end anchor applies to the catalog's `entrypoint`, `branch` and `forkOf` patterns and to the matching catalog checks. A dead in-page link's `#fragment` is now described as the URI reference it is.
- Text from the catalog and from GitHub is now encoded for the spot it lands in. A description with a `|` could split a table row, a title with `](` could start its own link, and `<` could open an HTML element. The README now escapes those, turns `&`, `<` and `>` into entities, keeps each value on one line, and drops control characters and the bidi characters that can make text display in a different order than it was written. The catalog check refuses those characters outright and names the code point. It also holds `entrypoint` and `branch` to a strict shape, because both are pasted into the install one-liners, where a `$` or a quote would change the command. The schema now sets length limits on the public text fields. The feed keeps the raw text, since JSON already escapes it.
- Release verification, when turned on, now checks a different slice of the release assets each week instead of the same first four in catalog order forever. The slice comes from the UTC week, so the same week always checks the same assets and consecutive weeks walk through all of them. An asset that can't be downloaded is now a warning, not a failure, since in an unattended run that's usually the network. Only a file that disagrees with its published checksum fails the run.
- The portfolio's row now links to portfolio.getparkerai.com and describes it as a self-hosted Astro site. It still said the site was hosted on GitHub Pages, where the old address has only redirected to the new one since 2026-07-28.
- Removed the fixed records of this repository's PR drills from the report code. Three functions returned "passed" evidence on every run: PR #14 and #16, their GitHub Actions run IDs, and a policy saying routine maintenance goes through pull requests, which stopped being true when the workflows were deleted. The published report never showed them, because with no workflows that section is marked not applicable, but a fork with workflows would have printed this history as its own. ## 2026-09-05

- Fixed six defects an adversarial review found in the day's own changes, three of them severe. The module lock demanded one Authenticode signer per package, but PSScriptAnalyzer legitimately ships three (Microsoft, a Microsoft third-party component certificate, and Json.NET), so `validate-local.ps1` would have thrown on every machine during bootstrap; the lock now records a signer set, and an unsigned file inside a package the lock calls signed is refused instead of skipped. Two guards used `PSObject.Properties` against `[ordered]` dictionaries, whose properties are `Count`, `Keys` and `Values` rather than the entries, so conditional headers were never sent and `ETag`/`Last-Modified` were never persisted, with each write erasing the previous run's validators. The retry time was computed and then dropped; it now reaches the report as `deferredRetries`. The injected-probe path used by tests also bypassed the cache entirely and produced different row fields than production, which is why the tests passed while the real path was broken, so both paths now share one cache decision and one row shape. And `registryLatest` came back as an empty string instead of null because a local variable collided case-insensitively with a `[string]`-typed parameter.
- Twelve of the generator's twenty-two blocking conditions now have a test that plants a real violation and watches the gate fire, rather than only proving the happy path. The control run measures which conditions the offline fixture already trips, and each case then asserts its own condition newly fired and that nothing else flipped. A cheap guard in the default lane refuses any new blocking condition that arrives with neither a reachability case nor a written, reasoned exemption, so the ten conditions that still need live-state injection seams are visible instead of forgotten.
- Link results are now cached by what the answer actually was.
